# AI 辅助逆向的研究方法

本页保留旧研究文档中可复用的方法，去掉依赖个人目录、固定运行时地址和临时脚本的操作。具体历史结果见 [案例稿](case-study.md) 与 [证据索引](evidence.md)。

## 研究闭环

```text
资源身份与边界
  → 静态定位处理路径
  → 运行时输入/输出采样
  → 离线实现与反例
  → 合成和真实样本回归
  → 宿主导出
  → 独立时序、蒙皮与姿态验收
```

任一环节失败都允许回退。不要同时带着三个未经验证的假设向前推进，再把错误归因到最后一个函数。

## 1. 先建立资源身份

在研究位流前，先列出类型、载荷位置、动作名称、帧数、帧率、SkelID 和相关骨架。

同一包可能混入多个角色或道具的动作。比较前应固定样本集合，记录排除条件，不能把不同日期或不同 SkelID 的统计合并成“全量正确率”。

## 2. 验证静态路径是否真的执行

字符串、交叉引用、调度表和常量池用于提出候选路径。反编译器未能恢复 SIMD 代码时，可阅读指令与常量，但这些工作不保证目标样本会调用该函数。

历史记录中，`FindKeyAndFillKeyCache` 在一组 3104 条 clip 的统计中未出现。这支持“先检查 opcode 覆盖再追该路径”，而不是“该函数在整个游戏中都是死代码”。

调试地址应记录可执行文件版本或哈希、模块基址、RVA 和符号线索，不把某次运行的绝对地址当作通用教程。

## 3. 让运行时提供可比较的输入与输出

由操作者在候选函数入口和返回处记录同一块数据，并核对线程、调用实例和输入身份。用同一调用的输入代入候选规则，比较实际输出。

如果需要协作采样，一次写清：

- 所研究的函数/调用条件与样本动作。
- 需要哪些寄存器、指针或内存范围。
- 捕获发生在入口还是返回。
- 如何确认两份数据来自同一调用。
- 如何脱敏和保存原始证据。

两个不同输入反解出相同参考量，是比单个漂亮样例更强的证据，但仍只支持其覆盖的布局与前提。

## 4. 验证方法也要接受测试

| 判据 | 能做什么 | 常见误用 |
|---|---|---|
| 单位四元数、有限值 | 排除明显非法值 | 当作旋转语义正确的证明 |
| 连续性 | 筛选候选排列 | 用恒定 idle 或低方差数据得出强结论 |
| 物理量级 | 排除数量级明显错误 | 认为“看起来像人”就等于恢复了原动作 |
| 结构不变式 | 约束位宽、边界、槽和骨映射 | 无条件把近似关系推广到所有布局 |
| 打乱对照 | 检查信号是否依赖正确结构 | 只比较顺序打乱，忽略数据本身相关性 |
| 绑定姿势或运行时真值 | 检验具体数值和映射 | 比较错误空间、比例或骨架 |
| 独立工具求值 | 验证真实交付产物 | 与被测实现共享同一错误前提 |

特别需要保留的反例：

- 最大分量不在 w 的四元数，能区分 swap 与 insertion。
- 分量位宽不等、零宽预测、跨 op27 块，能区分等分猜测与真实描述符。
- 有空洞/填充的 KeyCache 槽，能发现错误压紧与骨号偏移。
- 带 fixup 的零偏移，能发现空指针误判。
- 短长动作交换顺序与不同 fps，能发现 take 范围串扰。

## 5. 否定结论也需要前提

“某偏移不是参考表”只在所用布局假设正确时成立。历史上，连续布局的失败曾掩盖交错布局的正确位置。

每个否定结论记录被排除的完整组合：位置、字段序、对齐、量化尺度、样本集合和度量。不要把排除一个组合写成排除整个方向。

遇到不可能的度量值，先检查度量本身。例如四元数没有归一化却用单位四元数距离公式，可能产生误导性的负值。

## 6. 不要把所有可见错误都归因于压缩

主动画关节已正确时，仍可能存在：

- 缺失或错误的逆绑定矩阵。
- 辅助骨被相似名字误挂。
- twist 分摊或肩带锚点混合错误。
- 服装部件覆盖区域不配套。
- FBX 采样、单位、坐标或 take 时间问题。

沿“源动画 → 骨架 → 绑定 → 权重 → 产物 → 显示”分层定位，先保持原资产和主骨数据不变，不通过抬 root、整体缩放、改顶点或重刷权重掩盖问题。

## 案例发布检查

使用“假设—反例—修正—验证”的证据链，不用“AI 一次猜中”叙事替代过程。

模型归属、工时、成本、首创性和与其他模型的比较需要单独证据。没有记录时不填写数字，不把旧稿中的模型名直接替换为新模型名。

图片和视频还应对应动作、帧/时间、代码版本、FBX、相机和材质设置；不要把导出第 47 帧标成 49 帧源动画的末帧。
